This document defines the formal experimental framework used to evaluate and compare the **six inference scheduling algorithms** and the **evidence-grounded model cascading policy** in SETU-NETRA. ## 3. Workload Generation Profiles

To reflect real-world operational demands, benchmarks are evaluated across four standardized workload regimes generated by an automated load generator:

| Workload Profile | Request Composition | Arrival Distribution | Key Challenges Tested |
| :--- | :--- | :--- | :--- |
| **Profile A: Uniform Extraction** | 100% Short QA prompts ($< 100\text{ tokens}$). Target: Fast embeddings / SLM. | Constant rate ($\lambda = 5\text{ req/s}$). | Baseline scheduling overhead, pure dispatch efficiency. |
| **Profile B: Heterogeneous Tasks** | 30% OCR extraction (heavy), 40% short QA, 30% long synthesis ($> 500\text{ tokens}$). | Poisson process ($\lambda = 10\text{ req/s}$). | Convoy Effect (short requests blocked behind slow jobs). |
| **Profile C: Burst Traffic** | Alternates between idle ($\lambda = 2$) and burst spikes ($\lambda_{\text{burst}} = 25\text{ req/s}$). | Markov-modulated Poisson Process. | Queue buffer overflow, worker saturation, and backpressure. |
| **Profile D: Degraded Worker** | 3 workers, but 1 worker experiences synthetic $500\text{ ms}$ processing delay. | Continuous stream ($\lambda = 8\text{ req/s}$). | Dynamic re-routing around impaired or slow workers. |

## 4. Mathematical Formulations of Evaluation Metrics

### 4.1 Latency Percentiles ($p50, p95, p99$)
Let $T = \{t_1, t_2, \dots, t_N\}$ be the sorted array of end-to-end request latencies in milliseconds ($t_1 \le t_2 \le \dots \le t_N$):
$$p_k = T\left[\left\lceil \frac{k}{100} \cdot N \right\rceil\right]$$
* **$p50$ (Median):** Typical user experience.
* **$p95$ / $p99$ (Tail Latency):** Measures queue backlog and worst-case delay under congestion.

---

### 4.2 System Throughput ($\text{RPS}$)
The rate of successfully completed requests per unit time:
$$\text{Throughput} = \frac{N_{\text{successful}}}{\Delta t_{\text{total}}} \quad (\text{Requests per Second})$$

---

### 4.3 Worker Utilization ($\rho_w$)
The proportion of total benchmark time that worker $w$ spends actively processing tasks:
$$\rho_w = \frac{\sum_{i \in \text{Completed}_w} \text{ExecutionTime}_i}{\Delta t_{\text{total}}} \in [0.0, 1.0]$$
The **Load Imbalance Factor ($\sigma_\rho$)** across $K$ workers measures scheduling equity:
$$\sigma_\rho = \sqrt{\frac{1}{K} \sum_{w=1}^K (\rho_w - \bar{\rho})^2}$$

---

### 4.4 Scheduling Dispatch Overhead ($\tau_{\text{sched}}$)
The CPU time consumed exclusively by the scheduler to compute its routing decision:
$$\tau_{\text{sched}} = t_{\text{dispatch\_end}} - t_{\text{dispatch\_start}} \quad (\text{measured in microseconds, } \mu s)$$
*A valid scheduler must execute in $\tau_{\text{sched}} < 200\mu s$ to avoid becoming a bottleneck.*

---

### 4.5 Citation Grounding Precision ($P_{\text{cite}}$)
Measures factual grounding in generated answers:
$$P_{\text{cite}} = \frac{\text{Count of Valid Citations Matching SQLite Bounding Boxes}}{\text{Total Citations Asserted in Output}}$$
*A certified answer must achieve $P_{\text{cite}} = 1.0$ ($100\%$).*

---

## 5. Statistical Rigor & Significance Testing

To eliminate random noise and operating system scheduling jitter:
1. **Repeated Trials:** Every benchmark configuration is executed across **5 independent trials** with different random seeds.
2. **Confidence Intervals:** All reported metrics display $95\%$ confidence intervals:
   $$\bar{X} \pm t_{0.025, N-1} \cdot \frac{s}{\sqrt{N}}$$
3. **Hypothesis Testing:** When comparing two algorithms (e.g. CAS vs. Round Robin), we compute the **two-tailed Wilcoxon signed-rank test** across matched request pairs. Performance differences are only reported as statistically significant if $p < 0.01$.
